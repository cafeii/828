# lsa300m 下游评估开发计划（2026-09-01）

目标：对 `20260831-2009-lsa300m-main` 产出的两个 ckpt（gdn2_gqa_340M / gdn2_lsa_340M，各 15B tokens）
完成 docs/experiment.md 规定的三套评估：lm-eval 十项 + RULER 四任务 + JRT 六任务。

已确认决策：
- 接入方式：**本地 HF 兼容 wrapper**（不转 fla HF 格式）——直接加载工作区 lit_gpt 模型与 ckpt，避免两份实现的数值对齐风险
- RULER 长度网格：**1K/2K/4K/8K**（4K 为训练长度，8K 看外推）

## 现状要点（已勘察）

- `mixers/gdn2.py` forward 已完整支持 fla 风格 `past_key_values`（prefill chunk / decode fused_recurrent / T<=64 自动切 recurrent），增量推理的底层就绪
- 缺口在 `model.py`：`Block.forward` RNN 路径调用 `self.attn(n_1, attention_mask=None)`，未穿透 cache；`GPT.forward` 的 kv cache 逻辑只服务 attention 路径
- lm-eval（`third_party/prefix-linear-attention/lm-eval-harness`）：`lm_eval/models/local_lm.py` 已示范"现成 model 对象包进 HFLM"；loglikelihood 任务只需 forward logits
- JRT：同一 harness，**必须用 `prompt_scripts/run_jrt_prompt_hf.sh` 的 prompt 版任务名**（based_swde 等，GDN README 明确警告裸任务名结果差异巨大）；需 generate
- RULER（`third_party/RULER`）：`scripts/pred/model_wrappers.py` 有 HuggingFaceModel/MambaModel 先例，加自定义 wrapper 分支即可；需 generate
- ckpt 在服务器：`outputs/20260831-2009-lsa300m-main/{gdn2_gqa_340M,gdn2_lsa_340M}/final-model-ckpt.pth`（4.3GB，fabric 保存）
- 服务器无外网：评估数据集需 `HF_ENDPOINT=https://hf-mirror.com`（集群手册 L208）或本地下载上传

## 阶段 1：推理路径打通（本地开发 + CPU 单测）

1. `model/lit_gpt/model.py`：GPT/Block 增加 `past_key_values`/`use_cache` 穿透到 RNN mixer；
   训练路径（不传 cache）行为严格不变
2. 新建 `scripts/eval/wrapper.py`：
   - `LitGPTForCausalLM`：HF 兼容（`forward(input_ids, past_key_values, use_cache) -> logits/past_key_values`、
     `generate` 贪心解码、fla Cache 初始化）
   - ckpt 加载（fabric state dict 键名适配）、Llama-2 tokenizer 绑定
3. CPU 单测（naive mode，`tests/test_eval_wrapper.py`）：
   - 随机小模型：prefill+逐 token 增量 decode 的 logits == 一次性全量 forward（容差内）
   - GQA 与 LSA 两种 config 各测一遍

## 阶段 2：三套框架接入（三条线可并行 subagent）

按 CLAUDE.md 规则，第三方代码改动一律补丁注入：`third_party/<repo>/patches/` + `PATCHES.md` 记录。

1. **lm-eval**：仿 `local_lm.py` 注册 `lit_gpt` model 类型（包 HFLM）；十项任务清单脚本
   （FineWeb-test ppl 单独用 val litdata 算，训练 val loss 可交叉验证）
2. **JRT**：同 harness 的 generate 路径，任务名取自 `run_jrt_prompt_hf.sh`
   （based_swde/based_swde_twice/based_fda/... context_length=1000, answer_length=50, cutting_context）
3. **RULER**：`model_wrappers.py` 补丁加 `litgpt` 分支；`config_models.sh`/`run.sh` 配置
   4 任务（S-NIAH-1/2/3, MK-NIAH-1）× 4 长度（1024/2048/4096/8192）

## 阶段 3：评估数据准备（服务器）

1. 登录节点带代理试 `HF_ENDPOINT=hf-mirror.com` 拉数据集（lm-eval 各任务、
   hazyresearch/based-* JRT 数据、RULER 的 PaulGrahamEssays）
2. 失败回退：本地下载 → rsync 上传 `datasets/lzc_rnn/eval_data/`
3. eval 相关 pip 依赖装入 `lzc-rnn` 环境（lm-eval -e 安装、RULER 依赖 wonderwords 等；
   属 lzc-* 自有环境，装前列清单留档）

## 阶段 4：服务器冒烟

单 ckpt 小规模端到端：PIQA（loglikelihood）+ S-NIAH-1@1K（generate 长文）+ SWDE limit=50（generate 短文）
各跑通、抽查输出合理性（如 PIQA acc 应显著 >0.5）。

## 阶段 5：全量评估提交

- 2 模型 × 三套评估，按框架拆 sbatch（单卡即可，best-fit 碎片节点）
- 逐样本原始输出写 `outputs/<exp-id>/eval_raw/`（回收时排除）

## 阶段 6：结果收集与汇报

汇总表（GQA vs LSA 全指标对照），回收本地，更新 manifest，与 GDN2 论文口径对比。

## 风险

- 8K 外推可能触发 rope/max_seq_length 相关 assert（RNN 无位置编码理论无限长，但代码里
  block_size 相关检查需核）→ 阶段 1 一并处理
- hf-mirror 可能缺 hazyresearch 数据集 → 走本地上传回退
- lm-eval harness 版本较老（prefix-linear-attention fork），依赖可能与 lzc-rnn 的 torch 2.9 冲突
  → 冒烟阶段发现即报告
